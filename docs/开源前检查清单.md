## 二、他人部署需要做的事

README 里应写清楚：

1. 注册小程序，拿到 AppID，填入 `project.config.json`
2. 开通云开发，创建环境，设置 `TCB_ENV_ID`（**必须替换**，代码默认值指向原作者的环境）
3. 云数据库创建 `follows` 集合，权限设为「仅创建者可读写」
4. 上传部署 7 个云函数（getStreamerStatus / getUserFollows / toggleFollow / watchLive / notifyQuota / guardian / metaReader）
5. 安装微信开发者工具，打开项目根目录

**当前 README 已有这些内容**，「云环境 ID 必须替换」的提示见 README「环境配置」一节。

## 四、CI（已建成，2026-11 起）

现有两条流水线：

- `.github/workflows/ci.yml`：typecheck → lint → 单测 → check:rules
- `.github/workflows/weapp-build.yml`：带显式环境变量的小程序构建冒烟（防产物缺注入，坑 #5），支持 `workflow_dispatch` 手动补跑

注意：安全加固曾围绕 H5 本地服务展开；该服务已随 H5 端删除（见 AGENTS.md 坑位表 #14）。

## 五、安全相关的开源考量

当前小程序端只通过 `Taro.cloud` 直连云函数（微信注入 openid，天然按用户隔离）；
历史上的 H5 本地服务及其安全加固（回环监听 / CSRF / STRIDE 探针）已随 H5 端删除。

| 事项 | 开源后是否成立 |
|---|---|
| 云函数网关 `auth=false` | ⚠️ 小程序端不经网关；若他人扩展出公网 HTTP 入口，必须先加鉴权 |

## 六、多用户化的改动范围（如果真要做）

按 `docs/扩展接缝设计.md` 的接缝，需要改的只有：

1. 新增 `RestFollowRepository` 或让 `cloudFollowRepository` 支持多用户
2. 实现 `IdentityProvider`（需要匿名登录或设备 ID）
3. 云函数把 `_openid` 的获取方式抽象出来
4. 数据表加索引

**不需要改**：所有 page、hook、store、组件。
