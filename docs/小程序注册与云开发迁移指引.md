# 小程序注册与云开发迁移指引

> 给你（项目所有者）的操作手册。技术侧改动已全部就绪（watchLive 云函数 + 前端订阅入口 + CI），
> 只差「真实 AppID + 你自己的云环境 + 订阅模板」三样东西。
> 全程约 30 分钟操作，加 1 小时左右微信审核/部署耗时。

---

## 一、为什么现在是「半残」

`project.config.json` 的 `appid` 是 `touristappid`（游客模式）：

- 游客模式**无法使用云开发**——微信小程序端的关注/取关实际是坏的（H5 端不受影响，所以你日常用的是 H5）
- 游客模式**无法申请订阅消息**——云端开播提醒发不出去
- 注册一个真实个人小程序（免费）可以一次性解决以上全部

## 二、注册小程序（约 15 分钟）

1. 打开 https://mp.weixin.qq.com → 「立即注册」→ 选「小程序」
2. 邮箱激活 → 主体类型选**个人**（免费、无需企业资质）
3. 信息登记：管理员是你的微信号；名称填「播了么」，**若重名被占换个近似名**（个人名称唯一性按注册顺序）
4. 类目选择：工具 → 信息查询（个人可选，无前置资质要求）

注册完成后：后台「设置 → 基本设置」→ 复制 **AppID**（`wx` 开头 18 位）。

## 三、替换项目里的 AppID

编辑 `project.config.json`：

```json
"appid": "你的AppID",
```

就这一处。其余 `touristappid` 残留不影响。

## 四、开通云开发并创建环境（约 10 分钟）

微信开发者工具打开本项目 → 顶部「云开发」按钮 → 开通：

1. 选环境地域（推荐上海，网关域名同样式）
2. 创建新环境，名字随意（如 `bome-live`），**记下环境 ID**（形如 `bome-live-3gxxxxxx`）
3. 套餐：云开发是收费的，选最低档即可（个人自用的调用量级极小；价格以控制台实价为准）

> 复用旧环境 `bome-app-d6gb6gk0j89b15e5e` 不行：微信小程序的云调用只能到达**绑定本 AppID 账号**的环境。旧环境继续给 H5/本机脚本过渡用。

### 创建两个数据库集合

云开发控制台 → 数据库 →

|---|---|

## 五、部署 4 个云函数

微信开发者工具左侧 `cloudfunctions/` 下逐个右键 →「上传并部署：云端安装依赖（不上传 node_modules）」：

- `getStreamerStatus`
- `getUserFollows`
- `toggleFollow`
- `watchLive` ← 部署后**再右键一次 → 「上传触发器」**（首次部署必须做，否则每分钟巡检不启动）

## 六、切换构建/脚本的云端指向

代码里默认值还是旧环境 ID，用环境变量覆盖（这正是当初把环境 ID 集中的原因，不用改一行代码）：

```powershell
# PowerShell（当前会话）
$env:TCB_ENV_ID = "你的新环境ID"
$env:TCB_GATEWAY_HOST = "你的新环境ID-<地域数字>.ap-shanghai.app.tcloudbase.com"   # 看「云开发→静态托管→网关」的实际域名，H5 代理用

npm run build:weapp     # 小程序包（SUBS_TEMPLATE_ID 见第七步）
npm run build:h5        # H5 包（可选，H5 用旧环境也行）
```

要长期生效用 `setx`（Windows 用户环境变量），或在 `scripts/cloud-env.js` / `config/index.ts` 把默认值换成新 ID 并提交。

## 七、申请订阅消息模板（开播通知的第三块拼图）

小程序后台 →「功能 → 订阅消息」→ 公共模板库：

1. 搜「开播」，或退一步找**内容通知类**模板（thing/时间 字段组合）——个人类目能选的模板有限，**以库里实际能搜到的为准**
2. 选一个包含「通知内容(thing) + 通知时间(time)」字段的模板，**记下模板 ID**
3. 打开 `cloudfunctions/watchLive/watch-config.json`：
   - `templateId` 填开播通知模板 ID（告警可共用同一个，即 `alertTemplateId` 也填它）
   - 对照模板里的实际字段名改 `keys` 映射（如模板字段叫 `thing1/thing2/time2` 等，字段名以模板详情页为准）
   - 字段映射与取值器的对应关系由 `npm test` 守护（键名写错单测立刻红）
4. 重新「上传并部署」watchLive
5. 小程序端编译注入同一模板 ID：

   ```powershell
   $env:SUBS_TEMPLATE_ID = "你的模板ID"
   npm run build:weapp
   ```

## 八、端到端验证（照着点一遍）

1. 开发者工具运行小程序 → 订阅页 → 通知栏右侧出现「开启」按钮 → 点击 → 系统授权弹窗 → 允许 → toast「已开启开播提醒」
2. 云开发控制台 → 云函数 → watchLive → 「云端测试」（直接调用，无参）→ 返回 `{ code: 0 }`、日志有「本轮完成」
3. 关注一个**此刻正在直播**的抖音号 → 等 1~2 分钟 → 微信收到「XX 开播了」通知 → 点开落在该主播详情页
4. 真实关机测试：电脑关机状态下开播的主播，微信仍能收到——这是本次迁移的验收标准

## 九、切云端后本机链路的处理

- `watch-live.js` 保留为备用排查工具
- **不要两条链路同时常开**：状态文件互不同步，同一场直播会收到两条通知（详见《开播提醒云化方案.md》已知限制第 1 条）
- 切云后建议本机脚本 `node scripts/watch-live.js --reset` 后不再常驻

## 十、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 真机点「开启」无反应 | 模板 ID 没注入（compile 期还空） | `$env:SUBS_TEMPLATE_ID=` 后重新 build:weapp |
| 推送 errCode 43101 | 该用户没攒额度或额度已消费 | 正常，让用户再进小程序点一次「开启」 |
| 推送 errCode 200014 | 模板 ID 无效或 miniprogramState 不匹配 | 核对 templateId；体验版推送把 watch-config 的 miniprogramState 改 `trial` |
| watchLive 每 60s 报「查询失败」 | 抖音改版（不是部署问题） | 故障告警会自然触发；按 getStreamerStatus 的 `extractEscapedObject` 线索修解析 |
| 云函数间调用报无权限 | watchLive 的 config.json 未重新上传触发器/权限 | 重新右键部署 watchLive 并上传触发器 |
