## 二、启动命令

```powershell
# 构建（源码改动后必须执行）
npm run build:h5

# 启动网页服务（保持终端不关）
npm run serve:h5
# 访问 http://localhost:3000/#/pages/home/index

# 启动开播巡检（另一个终端，保持不关）
npm run watch:live

# 只跑一轮巡检（调试用）
node scripts/watch-live.js --once

# 发一条测试消息，验证微信链路
node scripts/watch-live.js --test-notify

# 清空巡检状态（下次运行静默重新记录，不补推历史）
node scripts/watch-live.js --reset
```

注意事项：
- 依赖安装需加 `--legacy-peer-deps`（webpack 版本冲突）
- PowerShell 里用 `npm.cmd` 或 `node`，不能直接跑 `.ps1`
- `dist-h5` 是 `config/index.ts` 里 `outputRoot` 按 `TARO_ENV=h5` 决定的，`serve-h5.js` 读的就是这个目录

## 三、架构与数据流

```
┌─────────────────── 浏览器 ───────────────────┐
│  Taro H5 (dist-h5)                           │
│  services/cloud.ts → fetch('/api/<name>')    │
└──────────────────┬───────────────────────────┘
                   │ 同源，无 CORS
┌──────────────────▼───────────────────────────┐
│  scripts/serve-h5.js  (localhost:3000)       │
│  ├─ /api/getUserFollows  ← 本地实现           │
│  ├─ /api/toggleFollow    ← 本地实现           │
│  └─ /api/其余            → CloudBase 网关代理 │
└──────────────────┬───────────────────────────┘
                   │ https
┌──────────────────▼───────────────────────────┐
│  CloudBase 云函数 HTTP 网关（auth=false）      │
│  getStreamerStatus：抓 live.douyin.com SSR    │
└──────────────────────────────────────────────┘

数据真源：scripts/follows.json
   ├─ serve-h5.js 读写（网页关注/取关）
   └─ watch-live.js 读取（巡检）
```

**关注列表只有一份**：`scripts/follows.json`。网页上关注的主播，巡检脚本下一轮立刻能读到，不存在两份数据不同步的问题。

**开播判定**：`cloudfunctions/getStreamerStatus/index.js` 抓 `https://live.douyin.com/{uniqueId}` 的 SSR 页面，括号配平提取转义 JSON，双重 `JSON.parse` 后读 `room.status`：`2` = 直播中，`4` = 未开播；`code: 0` 表示账号存在，`code: -1` 表示不存在。

**推送链路**：巡检发现 `offline → living`（或直播中开播时间跳变超过 5 分钟），调用本机 nanobot：
`nanobot trigger trg_EF5T5LHW "<消息>"` → gateway → 微信。

## 四、本轮会话完成的工作

### 1. 彻底清除伪造数据（用户质疑"发现数据是不是伪造的"后核实）

之前的问题：发现页是硬编码 mock；首页主打卡片初值来自 mock；我的页有假头像/假昵称/假统计；详情页有粉丝数/上次开播/历史直播。早期验收把这些笼统算作"验证通过"，是判断失误。

已处理：

| 位置 | 处理方式 |
|---|---|
| 发现页 / 搜索页 | 目录整体删除，`app.config.ts` 页面 6→4，tabBar 移除「发现」 |
| `src/data/` | 全部删除（10 条假主播、liveRecords、callMock 目标等） |
| 首页主打卡片 | 改用真实关注列表 + 实时状态，优先展示在播的那位；离线只显示真实的 `抖音号：xxx` |
| 我的页 | 删除假头像/假昵称/假 bio/"收录主播"统计/意见反馈/清除缓存；只留真实统计（订阅数、在播数）和 2 项菜单 |
| 主播详情页 | 删除 mock 列表/粉丝/上次开播/历史直播；改为关注记录 + `useLiveStatus` 真实状态 |
| `StreamerCard` | 删除离线分支伪造的"上次开播" |
| `services/cloud.ts` | **拆掉 `callMock` 回退机制**，失败一律抛错，结构上不可能再返回假数据 |

### 2. 修复首页「我的订阅」看不到真实主播的 bug

原实现用假列表 `streamers.filter(...)` 过滤，真实关注的主播根本不在假列表里。改为统一走 `useFollowsWithStatus`。验证方式：特意关注一个不在原假列表里的主播，确认其出现在页面上，验证后删除该测试记录。

### 3. 抽公共 Hook

新建 `src/hooks/useFollowsWithStatus.ts`，首页/订阅页共用"关注列表 + 实时状态合并 + 60s 轮询"，删掉订阅页里重复的约 40 行实现。

## 七、遗留问题（如实交底）

1. **主播详情页没有做过浏览器视觉验证。** 浏览器自动化工具连续 3 次 `IDE Command timeout`（WebView 未就绪），按规范停止重试。
   - 替代证据：路由已注册、`tsc` 与构建通过、构建产物零伪造字符串、hooks 调用在 early return 之前（无 hooks 顺序问题）
   - 待人工确认：打开首页点「详情」，应看到 名字 / 抖音 / `抖音号 54681081079` / `暂未开播` / `+ 关注` / 「主播信息」卡；**不应出现**粉丝数、上次开播、历史直播

2. **`offline → living` 真实开播推送未端到端验证。** 需要提供一个**此刻正在直播**的抖音号，加入关注列表后跑 `--once` 观察是否收到微信。测试消息链路此前已由用户确认"微信确实收到"。

3. **查询失败时 UI 会沿用关注记录里的旧状态**（通常显示"未开播"）。这是刻意的取舍，已在 hook 里注释，宁可显示旧状态也不显示伪造状态。

4. **`cloudfunctions/getStreamerList` 已失效但保留**：当前环境是 PostgreSQL，该函数里的集合查询必抛错，会退回硬编码 5 条。前端调用入口已删除，云函数本体没删。**不要再从前端调用它。**

5. **项目没有 git。** 建议尽快 `git init` 并提交一次，否则后续改动无法回滚。

## 八、踩坑记录（别重复踩）

| 坑 | 现象 | 结论 |
|---|---|---|
| Python 商店占位程序 | `nanobot trigger` 退出码 9009 | PATH 里的 `python` 是占位程序；真实路径是 `C:\Users\23374\AppData\Local\Programs\Python\Python314\python.exe`，必须写进 `watch-live.config.json` |
| 误报推送成功 | 日志说"已推送"，微信没收到 | `nanobot trigger` 的 exit 0 **只代表入队**，投递由 gateway 异步完成；失败只写 `C:\Users\23374\.nanobot\logs\gateway.log`。脚本日志已改为"已提交到 nanobot：Queued ..." |
| 服务不可用 | 浏览器打不开 | 多半是 `serve:h5` 进程死了（电脑重启后必现），与微信推送是两件独立的事 |
| 云函数 cors | 浏览器直连网关被拦 | 必须走 `/api/*` 同源代理，`serve-h5.js` 负责转发 |
| 云函数参数格式 | `event.body` 是 JSON 字符串 | 网关触发时需要用 `parseParams` 处理 |
| 静态资源缓存 | 改了代码页面没变 | HTML 里 `Cache-Control: no-cache`，资源引用带 `?cb=timestamp` |
